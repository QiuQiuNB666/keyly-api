## 第一步：先在 3300 测试版上跑

1. 浏览器打开 http://127.0.0.1:3300/login，用 `admin.local.txt` 里的管理员登录。
2. 确认支付合规声明（系统设置 → 集成 → 支付设置里的合规确认）。不确认的话，套餐接口会一律报错。这一步只能在网页上点，令牌做不了。
3. 个人设置 → 访问令牌 → 新建一个令牌：
   - 勾选 `billing:read` 和 `billing:write`，别的权限都不勾。
   - 有效期设几天就行。
4. 在终端里跑：

   ```bash
   cd ~/Downloads/keyly
   export KEYLY_BASE_URL=http://127.0.0.1:3300
   read -s KEYLY_ADMIN_TOKEN && export KEYLY_ADMIN_TOKEN   # 粘贴令牌，屏幕上不显示
   python3 keyly_plans.py            # 只打印要发的内容
   python3 keyly_plans.py --apply    # 写入，新建的套餐保持停用
   ```

5. 脚本写完会把后台存下的值读回来，逐项比对，最后打印 `Read-back check passed: 5 plans match.`。如果打印 FAILED，会列出哪个字段不对，退出码是 1。
6. 打开后台 → 订阅管理，点开「$80 / 28 天」，核对：
   - 价格 72，时长 28 天，每周额度 $20。
   - 重置方式「自定义」，604800 秒。
   - 「额度用尽后允许使用钱包余额」关，「允许余额兑换」关。
   - 状态「停用」。
7. （可选）用管理员把 ¥72 套餐绑给测试用户 `shotuser`，在他的钱包页确认能看到套餐、显示每周 $20。真正扣额度要等接上渠道才能测。

## 第二步：上线上

线上部署好以后，按第一步的 1–6 再做一遍，只把 `KEYLY_BASE_URL` 换成线上地址。

脚本按套餐标题判断是新建还是更新，重复跑不会生成重复的套餐。更新时会保留你在后台填过的 Stripe/Creem 商品 ID 和分组设置。

核对没问题后上架，两种方式任选一种：
- 在后台逐个启用。
- 跑 `python3 keyly_plans.py --apply --enable`。

部署时要注意：仓库自带的 `docker-compose.yml` 拉的是官方镜像 `calciumion/new-api:latest`，不是 keyly-api 这个分支。要用改过界面的版本，得从源码构建，或者用 iMac 上那份编译好的程序。

## 模型价：两种填法，上线前选一种

套餐里的「$1」只卖 ¥0.78–0.9：¥72 / $80 是 0.9，¥2338 / $3000 是 0.78。模型单价必须按这个「$」来标，套餐才不亏。

### 填法 A：模型价按套餐的「$」标（不亏，推荐）

卖价 = 人民币成本 × 倍率 ÷ 0.78。按最便宜的那档 ¥2338 来算，五档都不亏。最便宜那档用户用满，扣掉 3% 手续费，×1.3 的模型还剩约 20% 毛利，×1.5 的约 30%。单位是「$」每 1M token：

| 模型 | 倍率 | 高峰 输入 / 缓存 / 输出 | 空闲 输入 / 缓存 / 输出 |
|---|---|---|---|
| deepseek-v4-pro | ×1.3 | 15.02 / 0.5006 / 45.06 | 7.51 / 0.2503 / 22.53 |
| deepseek-flash | ×1.5 | 3.851 / 0.0770 / 15.40 | 1.926 / 0.0385 / 7.702 |
| qwen-plus | ×1.5 | 1.540 / 0.3081 / 3.851 | 不分时段 |

**代价：**

- 模型广场上 deepseek-v4-pro 会显示成输入 $15 / 1M，大约是 DeepSeek 官网美元价的 11 倍。懂行的人会觉得贵，其实是因为这里的「$」本来就便宜。
- 钱包充值和兑换码也要按同一个比例：¥0.9 = $1 额度，¥50 的码给 $55.5。站点的充值价格要从 7.3 改成 0.9，否则充钱包的用户要多付 8 倍。

deepseek-v4-pro 的计费表达式（后台该模型定价里切到「计费表达式」，粘贴）：

```text
weekday("Asia/Shanghai") >= 1 && weekday("Asia/Shanghai") <= 5 && ((hour("Asia/Shanghai") >= 9 && hour("Asia/Shanghai") < 12) || (hour("Asia/Shanghai") >= 14 && hour("Asia/Shanghai") < 18)) ? tier("peak", p * 15.02 + cr * 0.5006 + c * 45.06) : tier("off_peak", p * 7.51 + cr * 0.2503 + c * 22.53)
```

deepseek-flash：

```text
weekday("Asia/Shanghai") >= 1 && weekday("Asia/Shanghai") <= 5 && ((hour("Asia/Shanghai") >= 9 && hour("Asia/Shanghai") < 12) || (hour("Asia/Shanghai") >= 14 && hour("Asia/Shanghai") < 18)) ? tier("peak", p * 3.851 + cr * 0.077 + c * 15.4) : tier("off_peak", p * 1.926 + cr * 0.0385 + c * 7.702)
```

qwen-plus：

```text
tier("standard", p * 1.54 + cr * 0.3081 + c * 3.851)
```

### 填法 B：模型价按真美元标（你原文的算法，套餐会亏）

卖价 = 人民币成本 ÷ 7.2 × 倍率。deepseek-v4-pro ×1.3 高峰是 $1.625 / $0.0542 / $4.875。

模型广场上看着正常。但 ¥72 的套餐用户用满 $80，上游成本大约 ¥440，是售价的 6 倍。只有用户平均用不到两成额度才不亏。

### Claude：上架，按号池成本标（11-28 改）

货源自己搭号池，不用官方 Key。成本就用你给的 claude-sonnet-5（也就是现在的 5.5 代）：**$0.22 输入 / $1.10 输出**（真美元，每 1M token），大约是官方价（$2 / $10）的 11%。

套餐里那个「$」只值 ¥0.78，所以成本要先放大到套餐的 $ 再标：`套餐$ = 真美元成本 x 7.2 / 0.78 x 倍率`。按最便宜那档 ¥2338 算，五档都不会亏。

**claude-sonnet-5-5，套餐里的 $ 每 1M token：**

| 倍率 | 输入 | 缓存读取 | 输出 |
|---|---|---|---|
| x1.3 | $2.64 | $0.26 | $13.21 |
| x1.5 | $3.05 | $0.30 | $15.24 |

缓存读取按输入的 10% 算（后台的缓存倍率留 0.1 就行）。

看着比对方贵十几倍（对方标 $0.22 / $1.10），是因为两边的「$」不是一回事：我们的 $ 卖 ¥0.78，他们的 $ 大概是真美元。换算成人民币，我们 1M 输入收 ¥2.06，对方收 ¥1.58，只贵三成。

**claude-opus-5-5、fable-5-2、haiku-5-5：** 你给的数里只有 sonnet 的，其余按官方的 11% 估。官方价（5.5 这一代，2026-11）：opus 5.5 $4 / $20，fable 5.2 $8 / $40，haiku 5.5 $0.10 / $0.50。换成套餐价 ×1.3：opus 5.5 **$5.28 / $26.42**，fable 5.2 **$10.57 / $52.85**，haiku 5.5 **$0.13 / $0.66**。拿到真实号池报价再改。

第一版只上 sonnet 5.5 和 opus 5.5 两个。

**接法：**

- 前面放 sub2api（或同类）管订阅账号池，后面 new-api 建一个 Anthropic 类型的渠道指过去。
- new-api 认识 sub2api 的余额接口（`controller/channel-billing.go:434`，读 `/v1/usage`，能显示订阅的日/周/月上限），余额和用量能在渠道页看到。
- 套餐里 Claude 的额度消耗和 deepseek 一样，从周额度里扣。

**风险（就这一条，你认了就做）：** 订阅号池转 API 违反 Anthropic 条款，账号会被封，供货不稳。所以：

- 至少挂两个账号池渠道，互为备份。
- 上游只充够 1 到 2 周的用量。
- 页面写明「池子不稳时可能暂时不可用」，别让买家以为随时能用。
