## 四、还留着「New API」字样的地方和原因

`web/dist` 打包产物里搜 `New API` / `NewAPI`，剩下的分四类：
1. **必须保留的署名**：页脚署名、开源许可页的英文原句、仓库链接、「NewAPI © QuantumNous」。
2. **只有管理员看得到的后台文案**：渠道配置提示（「如果上游是 New API」等）、发信人占位「New API <noreply@…>」、首页内容占位「欢迎使用我们的 New API…」、插件市场相关文案。
3. **`index.html` 里的 `<title>New API</title>` 和 meta 标题**：页面一加载就被 SystemName 换成「Keyly API」（截图里每个页面的标题都是 Keyly API），只有关掉 JS 或者首屏前那一瞬间才看得到。这个默认标题没改，理由见下一条。
4. **代码里的默认站名常量、`public/favicon.ico`、`logo.png`**：都被系统选项覆盖了，买家看不到。

**为什么不改源码里写死的 new-api 品牌字样**：仓库自带的 `AGENTS.md` 规定，涉及 new-api / QuantumNous 的名称、署名、HTML 标题、meta、页脚、关于页等都不许删改。所以改名统一走 new-api 本来就提供的「系统名称 / Logo」设置，源码里原项目的署名和默认值一概不动。

## 五、升级 new-api 时怎么重新套上

1. 在旧版本 `src/` 里导出补丁：`cd src && git diff > ../keyly-frontend.patch`，新文件另外拷：`web/src/features/home/components/sections/keyly-hero.tsx`、`web/src/features/wallet/components/wallet-hero.tsx`、`web/src/assets/fonts/inter-latin.woff2`、`web/public/keyly-k.png`。
2. 在新版本里 `git apply --3way ../keyly-frontend.patch`。容易冲突的是 `public-header.tsx`、`footer.tsx`、`about/index.tsx`、`wallet/index.tsx`、`overview-dashboard.tsx`、`theme.css`；冲突时以新版本为准，照上面的表重新改。**注意新版本的 NOTICE 有没有变**，署名要求以新 NOTICE 为准。
3. 翻译文件冲突的话，只把新加的键补回去。
4. 系统选项存在数据库里，升级不会丢。
5. 构建：`cd src/web && DISABLE_ESLINT_PLUGIN=true VITE_REACT_APP_VERSION=$(cat ../VERSION) bun run build`，再 `cd src && go build -ldflags "-s -w -X 'github.com/QuantumNous/new-api/common.Version=$(cat VERSION)'" -o ../bin/new-api`，然后 `./stop.sh && ./start.sh`。
